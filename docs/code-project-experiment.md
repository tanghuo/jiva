# Jiva 源码 Demo

## 目标与取舍

固定以当前 Jiva 源码为内容，让人快速看清项目职责、结构和几条具体执行路径。用户明确否定了上一版的通用仓库浏览器形态：选择目录、六个平级标签、统计清单与全仓依赖图冲散了重点。

本版主画面只保留一张六模块地图及其上下文。模块说明、源码、目录与 Git 按需展开。入口为“更多 → Jiva 源码 Demo”。

## 画面与内容

- 页面自动读取 Jiva，取消项目路径输入和选择动作。
- 中心展示 React 界面、HTTP 入口、应用服务、本地存储、Agent 运行时、Electron 外壳六个模块。按职责整理布局，不把全部 import 边摊给读者。
- 点模块时，右侧只解释当前模块的职责及主要文件；“源码目录”作为右侧辅助视图，限定展示 src。
- “启动应用、添加文字、发送对话”是三条源码导览。逐步选择后，高亮相关模块，显示本步解释及精确源码入口。源码在宽阅读窗中打开、定位到相关行。
- 架构与脑图是同一份模块内容的两种显示方式。手机用可读的模块列表代替缩小的整幅画布。
- Git 是右上角次要入口，打开独立视图；沿用现成 Git Log / Diff View，展示提交图、文件、工作区、暂存区与 diff，仅提供读取。

## 真实性与边界

模块和执行路径由人工核对当前实现后整理在 `src/renderer/src/features/codeProjects/jivaGuide.js`。跨 HTTP/进程的箭头表达源码中的接口与职责关系，不表示运行时采样。单元检查逐项验证引用的文件和定位锚点存在。

源码和 Git 来自本机实际仓库，保留受限扫描及内存快照。外部接口改为 `POST /api/code-projects/jiva`，只接受空对象；服务端固定使用 Jiva 根目录，旧 `/open`、`/defaults` 接口取消。未修改资料库 schema；接口仍受本机认证与同源校验保护，LAN 与整理 worker 不可读取。

取消上一版未被当前体验使用的 AST 工作线程、函数索引、调用下拉、模块自动聚合及对应 Babel/Dagre 直接依赖。图形交互继续复用 React Flow，脑图复用 Mind Elixir，Git 复用 React Git Log 和 Git Diff View。许可副本保存在 `src/renderer/public/licenses/code-projects/`。

不执行导览中的业务操作或项目脚本，不提供 Git 写操作。源码目录或文件缺失时给出读取错误；Git 不可用时只影响 Git 视图。此 Demo 依赖 Jiva 源码工作区，尚未验证打包后的源码浏览。
