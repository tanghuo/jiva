# Antigravity 工作台接入

目标：在现有工作台选择 Google Antigravity，使用官方 ACP 服务端运行本机 Agent。

## 已验证事实

- Grok 与 Codex 由 `src/agent/engines/workbench.js` 分派；会话、审批、停止与恢复由工作台 service/repository 管理。
- 官方 ACP registry 提供 Windows x64 1.4.5，下载 SHA256 为 `d24f4c73c9f96d4f44384e281c855a56c72d8eaa9c5b0fad7ccb1635c6b63f50`。
- 本机桌面版已安装；ACP 初始化成功，声明图片及会话加载能力。
- ACP 在没有选定认证方法时返回 Authentication required。桌面登录是否可复用必须实测，不能假定共享凭据。

## 决策与边界

- 增加 `antigravity-acp` 引擎，使用官方本机子进程和 ACP stdio；不读取、复制或转换桌面版凭据，不反向代理模型端点。
- 默认从工作台 runtime 目录寻找已安装服务端，允许通过 `ANTIGRAVITY_ACP_EXECUTABLE` 指定路径。提供固定版本、校验哈希的安装命令；运行时不自动下载。
- 优先尝试 session/new，认证需要时明确报错。账号连接由用户明确触发；不在每次模型检测时重复打开浏览器。
- 使用服务端模型列表和请求审批模式，拒绝持久允许、自动放权和未知宿主请求。不声明操作系统沙箱；启动前要求用户接受原生文件访问与配置边界。
- 本期只提供原生 Agent，不注入 Wiki/付费工作流工具；不让受限工作流使用此引擎。
- 文本、计划、工具状态按 ACP 转换；原生工具的详情与 diff 仅按服务端实际返回展示。未拥有完整修改前记录时不提供撤销。
- 会话加载须得到服务端确认，失败不新建替代、不自动重发。取消通过 session/cancel；强制关闭使用现有进程树清理。
- 人工审批无期限，等待审批期间暂停执行请求超时；引擎退出会释放等待并标记未知结果。

## 验收

使用协议 fixture 覆盖认证失败、模型选择、文本/图片、审批允许/拒绝、取消、断连、恢复和失败不重发；服务测试覆盖接入菜单、原生信任和不注入应用工具；UI 测试覆盖选择引擎及审批。实际安装初始化和登录可用性单独记录，不以 fixture 冒充真实模型验证。

## 实施验证与评审

- 2026-10-31：官方 1.4.5 在本机完成个人 OAuth，后续检测与对话无需再次 authenticate；Gemini 3.8 Flash 真实两轮及跨进程恢复通过；原生文件允许一次/拒绝均核对实际文件。
- 接入测试包含账号连接去重及服务关闭取消认证、24 小时审批等待、断连、取消、恢复失败不替代、模型/强度/模式确认及应用工具隔离。
- 工作台集成测试通过；Antigravity 菜单、原生信任和单次审批 UI 通过，模型检测没有触发 connect。
- 更广 UI 回归中，旧聊天转换用例在进入工作台前因 Codex 尚未连接而无法发送；该边界不由 Antigravity 适配器修改。
- 架构检查在未由此次接入修改的 workbenchSurface.css、workflow.css、wiki.css 中报告已有颜色/控件尺寸规范违规，未扩大本次修复范围。
- 官方工具审批占位 ID 与执行 ID 可能不同，且占位状态未必代表实际结果；保留服务端事实，不将无法关联的审批差异当成已执行修改。

评审结论：接入范围内通过。实际图片、终端及其他原生工具尚未逐项实测；其边界由官方原生运行时管理，不宣称具备 Grok 文件网关的目录限制和撤销能力。


## 统一自动审批（2026-11-01）

- 问题：ACP 中间档 `auto_edit` 只批准编辑，直接称为自动审批会使 `git status` 等普通查看操作的审批行为与其他引擎不一致。
- 当前 ACP 的原生模式为 `default / auto_edit / yolo`；CLI 的 `auto` 与 ACP 不能混用。依据：[官方 ACP 发布说明](https://antigravity.google/docs/changelog)和 [CLI 模式说明](https://antigravity.google/docs/cli/modes)。
- 决策：保留三个原生模式映射，自动档由工作台补充有限的只读命令批准策略。只有已确认自动档的活动轮次、`execute` 请求、完整匹配的只读命令以及真实路径位于项目内的目录可以自动返回允许一次。其他请求保留原有审批。全部允许仍使用 `yolo`。
- 只读匹配限定为状态、当前分支、仓库路径与当前目录查询；不按命令前缀放行，不接受复合命令、重定向或额外执行字段。此策略不执行任意 Shell 风险分类，也不提供 CLI 原生沙箱。
- 自动批准写入 `approval.automatic` 事件，保留实际请求、轮次模式和原因；模式变更仍从下一轮生效，停止与恢复沿用现有生命周期处理。没有数据迁移或自动重发。
- 验收：`git status` 在自动档不出现审批卡；手动档仍询问；未识别命令、复合命令、项目外目录与指向项目外的目录链接继续询问；原生编辑和全部允许的协议测试继续通过。
- 实机模式探测本次返回 `AUTH_REQUIRED`，因此真实账号执行结果未验证；协议、服务和 UI 测试分别验证上述边界。
