# Jiva · 磁力 → 115 → 本地图集：最终产品方案

> 日期：2026-11-02  
> 状态：产品方案定稿；外部接口可行性仍需实测，不代表已实现。  
> 目标：在 Jiva 粘贴磁力后，后台获取文件、准备图集，用户确认后完成导入，并能在失败或应用重启后继续。

## 1. 核心决策

1. 第一版提供一条内置模板「磁力导入图集」，不做通用节点编辑器。
2. 磁力默认是任务的来源，不新增磁力素材类型；任务创建后立即持久化，失败也保留来源。
3. 115 连接、下载能力、解压工具和工作流可分别管理、引用；是否称为元素，不决定是否出现在内容库。
4. 流程按「获取文件 → 判断内容 → 准备导入 → 确认导入」组织，支持一次任务产生多个图集。
5. 第一版必须确认导入，但通过持久化的「待确认」队列完成，不以强制弹窗阻塞后台任务。
6. 目标空间在创建任务时固定，不随用户之后切换空间而变化。
7. 第一版就具备持久化进度、阶段恢复和导入去重；不提供笼统的“失败全部重跑”。
8. 导入成功后默认清理本地中间文件；不自动删除 115 远端文件或任务。

## 2. 用户体验与范围

用户在「导入」入口粘贴磁力，选择 115 连接和目标空间，提交后即可离开当前页面。任务继续在应用后台运行；关闭应用后，本地执行停止，下次启动恢复，远端离线任务可能继续。

文件准备好后，任务进入「待确认」。用户查看拟生成的图集、图片数量、标题、标签、目标空间和跳过项，调整并确认。导入完成后可以打开图集，也可以追溯到原始链接及处理记录。

### 第一版包含

- 单条磁力创建任务；多条任务可在队列中管理。
- 一个可用的 115 连接接入路径，优先验证扫码；Cookie 作为手动配置或排障方式。
- 远端离线下载、结果文件定位、本地下载。
- 图片目录及普通未加密 ZIP 的处理。
- 一个任务生成一个或多个图集。
- 待确认预览、导入、取消、按阶段重试和重启恢复。
- 来源追溯、结果关联、缓存占用展示及清理。

### 第一版不包含

- 新增磁力素材类型或专门的磁力收藏管理。
- 通用节点画布、多网盘适配、完整网盘文件浏览器。
- 本地 BT 下载或做种。
- RAR、7z、分卷包、加密包及递归解压嵌套压缩包。
- 视频等非图片内容的自动入库。
- 无需确认的全自动导入。
- 自动删除远端资源，或在分享内容中携带账号凭证和下载缓存。

## 3. 对象边界

| 对象 | 职责 | 展示位置 |
|---|---|---|
| 来源记录 | 保存原始磁力、规范化标识、来源页和可选标题 | 任务详情；图集来源追溯 |
| 115 连接 | 管理账号授权和连接状态 | 设置中的连接管理 |
| 获取、解压、导入能力 | 执行具体操作，返回结构化结果 | 内置步骤；无需内容卡片 |
| 工作流模板 | 定义处理顺序、参数和默认策略 | 工作流区 |
| 运行实例 | 保存一次任务的输入、进度、中间产物和结果 | 导入任务列表 |
| 图集及图片 | 持久保存可使用的内容 | 创建任务时选定的内容空间 |

“万物皆元素”可以表达对象可组合、可引用的产品理念，不要求第一版统一底层存储，也不要求所有对象出现在内容库。工作流模板只引用连接，不包含凭证。

磁力任务自身已经能满足失败留档。以后若出现对未下载来源进行标签、分类和长期收藏的明确需求，再增加收藏入口或内容类型。

## 4. 完整流程

```text
粘贴磁力，选择连接和目标空间
  → 校验输入并持久化任务
  → 提交或关联已有的远端离线任务
  → 等待远端完成
  → 精确定位结果文件或目录，建立文件清单
  → 下载至任务专属缓存
  → 判断内容：图片直接扫描，ZIP 解压后扫描
  → 生成图集导入计划
  → 待确认：调整图集标题、标签及选中项
  → 按已确认计划导入
  → 保存来源与一个或多个图集的关联
  → 标记成功，按策略清理本地缓存
```

### 内容处理规则

| 内容 | 处理方式 |
|---|---|
| 图片文件或图片目录 | 扫描并生成图集计划 |
| 一个或多个普通 ZIP | 分别解压至隔离目录，统一生成计划 |
| 图片与其他文件混合 | 图片进入计划，其他文件列入跳过清单 |
| 加密包、不支持的压缩格式、嵌套压缩包 | 标记无法处理，允许用户在确认时明确排除 |
| 没有任何可导入图片 | 不生成空图集；提示原因，保留结果供处理或清理 |

远端清单能够识别的无关文件可不下载；ZIP 内部内容在解压扫描后判断。不承诺第一版按压缩包内单文件进行远程选择下载。

有可用图片但同时存在无法处理项时，不静默丢弃；必须在预览中展示并由用户确认排除。没有可用图片时进入待处理状态，用户可取消，或在问题修复后重试。

## 5. 图集导入规则

复用现有图集分组、图片校验、存储和去重能力，不另建一套图片入库逻辑。交互预览与后台执行应使用同一份导入计划，后台任务不能依赖某个页面一直打开。

- 每个直接包含图片的目录形成一个候选图集；子目录中的图片按各自目录分组。
- 一个任务可以生成多个图集，任务与结果之间是一对多关系。
- 紧邻父目录可作为标签候选，用户在确认时调整。
- 以真实资源目录为扫描基准，不把任务 ID、缓存目录或解压隔离目录变成标题、标签。
- 根目录图片缺少合理标题时，用资源名作为候选，并允许修改。
- 现有图集容量和图片格式限制继续生效；超限必须在预览中说明，不静默截断。
- 已确认计划保存文件清单及版本。文件变化或计划重建后，需要重新确认。
- 目标空间在创建任务时固定。导入前若空间已删除或不可用，进入待处理状态，不自动改投其他空间。

### 当前代码事实及衔接要求

- `src/shared/domain/elements.js` 对外使用 `album` 等字符串类型，不应把草稿中的 `kind=6` 当成通用接口约定。
- `src/shared/domain/albums.js` 已提供目录分组、父目录标签候选和图集输入校验。
- 当前图集 `sourceUrl` 只接受 HTTP(S)。磁力应存入任务来源记录，通过任务与图集的关联追溯；不能直接塞入现有字段。若有原始网页地址，可继续用于 `sourceUrl`。
- `src/server/application/elementService.js` 已有图片导入入口；任务级幂等和恢复能力仍需设计、验证，不能仅凭现有图片去重认定已经具备。

## 6. 任务状态与恢复

运行状态与当前阶段分开记录，避免把登录失效、等待确认、下载失败都混成一个失败状态。

| 运行状态 | 含义 |
|---|---|
| 排队中 | 已持久化，等待执行资源 |
| 运行中 | 正在执行某个阶段 |
| 待确认 | 导入计划已准备好，等待用户确认 |
| 待处理 | 需要重新登录、处理不支持内容或解决目标空间问题 |
| 失败 | 当前阶段失败，可根据原因重试 |
| 已取消 | 停止本地执行；保留记录及已产生结果 |
| 已完成 | 已确认计划全部落库，来源与结果关联已保存 |

阶段包括：远端提交、远端等待、结果定位、本地下载、解压扫描、导入。记录最近完成的检查点、当前阶段、错误原因及可用操作。

### 恢复原则

- 远端已完成、本地下载失败：继续下载，不重新提交离线任务。
- 提交远端任务后响应丢失：先核对远端状态，不能盲目重复提交；无法消除歧义时进入待处理。
- 登录过期：等待原账号重新登录；更换账号不能直接沿用旧账号的远端文件标识。
- 应用重启：读取持久化记录，核对远端状态、本地文件和导入记录后继续；待确认任务仍保持待确认。
- 部分导入成功：保留已导入结果和逐项记录，仅继续未完成项。
- 来源关联写入失败：重试关联写入，不再次创建图集。
- 短暂网络错误可有限退避重试；登录失效、配额不足和不支持格式不进行无限重试。
- 取消在安全检查点停止后续处理，不回滚已导入图集，也不等同于取消远端任务。界面明确提示远端可能仍在运行。

任务进度按阶段展示。远端只有排队或运行状态时显示状态，不伪造百分比；下载和导入阶段在有可靠总量时显示进度。

## 7. 持久化与去重边界

以下是最低信息要求，不预设新增哪些表；实施时优先复用现有工作流运行设施。

| 信息 | 最低内容 |
|---|---|
| 输入快照 | 原始来源、规范化来源标识、连接 ID、目标空间 ID、模板版本、缓存策略 |
| 执行记录 | 运行 ID、状态、阶段、检查点、错误、重试次数、时间 |
| 远端映射 | 账号身份引用、远端任务标识、结果目录或文件标识 |
| 本地产物 | 文件清单、稳定文件标识、路径、完整性状态、缓存占用 |
| 导入计划 | 计划版本、候选图集与成员、排除项、用户确认记录 |
| 导入结果 | 图集映射、逐项导入结果、来源关联、完成状态 |
| 清理记录 | 待清理路径、清理状态、失败原因 |

去重分三个层次处理：

1. **提交去重**：按规范化资源标识、账号和目标空间识别相同进行中任务，引导打开已有任务；已有成功结果时展示结果，并允许用户明确另建任务。
2. **恢复去重**：同一运行中的候选图集和文件具有稳定标识，重试不得重复创建图集或重复添加成员。写入结果与恢复记录需保证一致，崩溃后可核对。
3. **内容去重**：复用既有图片内容去重规则及空间边界，不把相同来源直接等同于已经成功导入全部内容。

外部下载和解压不占用数据库长事务。恢复以可核对的持久化结果为准，不只依赖内存中的“步骤成功”。

## 8. 缓存、安全与成功判定

### 缓存规则

- 每次运行使用独立缓存目录；完整文件和下载中的临时文件明确区分。
- 默认在导入成功后删除下载副本及解压中间文件；允许开启“保留源压缩包”。
- 待确认、失败、待处理和取消任务不立即清理，展示占用并提供手动清理。
- 手动清理前说明后果：可能需要重新下载或重新生成计划；不删除已入库内容。
- 第一期不自动按时间清除未完成任务缓存，避免破坏恢复能力。
- 清理仅限已验证属于该任务的缓存路径；不触及内容存储或远端文件。

### 成功标准

已确认的图集及图片全部持久保存，逐项执行结果可恢复，来源与所有结果图集的关联已写入，才标记完成。用户明确排除的项目不计入待完成项，但需保留在结果摘要中。

缓存清理是独立后续动作。清理失败显示“导入完成，缓存待清理”，不触发重新导入。

### 执行限制

- 下载和解压设置可配置的字节数、文件数、磁盘余量及执行时间限制；实施验证时确定默认值。
- 解压路径必须限制在本次任务目录，拒绝目录穿越、绝对路径和可越界的链接项。
- 限制实际解压量，不只相信压缩包声明的大小；第一版不递归展开嵌套包。
- 文件是否可入库以实际图片校验为准，不仅依赖扩展名。
- 凭证由本机安全存储管理，不进入任务输入快照、内容表、普通日志、模板或分享包。

## 9. 115 集成与技术验证

参考项目：[SheltonZhu/115driver](https://github.com/SheltonZhu/115driver)。README 列出 Go 库、CLI、Cookie／扫码登录、离线任务、文件下载及 JSON 输出；这些是项目声明，不等于 Jiva 已验证整条链路。

建议由本地后台服务通过受控适配层调用 CLI 或薄封装进程，渲染层只接收结构化状态。优先验证 CLI JSON 路径；若凭证、恢复或文件映射接口不足，再采用薄封装，不提前锁死实现。

README 说明 CLI 默认使用配置文件保存凭证，因此不能把“调用 CLI”等同于“已经满足本机加密存储”。接入验证必须覆盖凭证注入、落盘和日志行为，避免秘密出现在命令行参数或普通配置中。

### 开发前必须通过的可行性验证

1. 使用真实账号完成认证及一条实际磁力任务。
2. 任务完成后，可可靠定位它生成的文件或目录，不用模糊文件名猜测归属。
3. 能递归枚举结果并正确下载；覆盖失效下载地址的重新获取及中断恢复策略。
4. 能识别登录失效、远端失败、排队和结果为空等状态。
5. 可处理远端提交成功但本地未收到响应的核对场景。
6. 凭证交付方式符合本机安全存储要求。

该验证由接入实现负责人承担。若无法可靠映射远端结果，应先调整接入方案，再实施完整交互；产品定稿不消除这个技术门槛。

## 10. 界面最小集合

1. **创建导入任务**：磁力、115 连接、目标空间、保留源压缩包选项。
2. **任务列表与详情**：当前阶段、实际进度、待确认入口、错误原因、重试／取消、缓存占用及结果图集。
3. **图集预览**：复用现有导入体验，展示分组、数量、标题、标签、跳过项及确认操作。
4. **115 连接设置**：登录、连接状态、重新登录和断开连接；被任务引用的连接断开后，相关任务进入待处理。

工作流入口可以打开这条内置模板，但用户无需理解节点或先搭建流程。完成后提示结果，待确认或需要处理时提示用户；正常后台轮询不反复打扰。

## 11. 实施顺序

1. **验证外部闭环**：认证 → 提交磁力 → 定位结果 → 下载本地，记录真实接口与错误行为。
2. **打通本地图集准备**：使用本地目录和 ZIP 验证扫描、分组、跳过项、预览与入库复用。
3. **加入持久化任务执行**：衔接远端步骤，补齐检查点、启动恢复、任务与成员去重。
4. **完成用户界面和清理**：任务列表、待确认、连接管理、结果追溯及缓存操作。
5. **做故障验收**：完成下列恢复与一致性场景后开放功能。

先确定最低任务契约，再做窄链路实现；不先建设通用工作流引擎，也不把任务恢复拖到后续版本。

## 12. 验收标准

- 图片目录和普通 ZIP 都可进入预览并成功导入；一次任务可生成多个图集。
- 切换当前空间不会改变任务目标；目标空间失效时不会导入到其他空间。
- 临时目录名不会进入图集标题或标签。
- 待确认任务在重启后仍可查看和确认，不依赖之前的页面或弹窗。
- 远端完成后下载失败，只恢复下载；远端提交结果不明时不会盲目再次提交。
- 登录失效后可通过同账号重新登录恢复。
- 导入一部分后终止进程，重启继续不会重复创建图集或成员。
- 关联写入失败后恢复，不重新导入图片。
- 不支持内容和空结果明确可见，不静默丢弃或创建空图集。
- 取消后不会继续新增导入项；已经完成的结果和远端仍可能执行的事实清晰可见。
- 解压越界及资源超限能够阻止，失败不影响已有内容。
- 成功后可追溯来源及全部结果；清理失败不改变导入成功状态。
- 凭证不会进入内容数据、运行快照、普通日志或分享内容。

## 13. 后续演进

首版稳定后，根据使用数据再决定增加来源收藏、可信模板自动导入、更多压缩格式、多网盘和可编辑节点。抽象应来自已经验证的重复需求；第一版交付重点是可靠的收集、确认、导入与恢复闭环。
