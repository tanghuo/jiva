# 磁力导入图集 · 首版实施

2026-11-02。产品依据：[最终方案](./jiva-磁力115导入工作流-最终方案.md)。

## 使用

开发环境先运行 `npm run build:115`，再启动后端。需要 Go 1.24+；Windows 打包也会执行此构建并把辅助程序包含在应用中。终端网络无法访问 Go 模块服务时，可为构建进程设置 `GOPROXY`。

侧栏「磁力导入图集」和工作流首页的内置模板通向同一个持久化任务队列。设置 → 115 连接支持扫码、原账号重新登录和断开。首版安全存储使用 Windows DPAPI，仅在 Windows 开放；原版 CLI 的明文 Cookie 配置不会被导入。

创建任务时选择连接与目标空间，粘贴单条 BTIH 磁力。进行中的相同来源会返回已有任务；已有成功结果时，勾选「另建任务」才创建新运行。可用 `node tools/torrent-magnet.mjs <torrent文件路径>` 从本地种子计算磁力，工具对原始 info 字节计算 SHA-1。

支持在内容库粘贴 `.torrent` 文件或磁力文字，自动打开磁力导入表单；在导入页面可粘贴、拖入或通过「选择种子文件」读取种子。Windows 资源管理器复制文件时，从本机剪贴板读取文件列表作为回退。种子最多 16 MiB，解析后显示识别提示，需要点击「创建导入任务」才开始远端处理。解析接口只接受种子二进制，剪贴板接口只读当前剪贴板内的单个种子路径，不接受页面传入任意本地路径。

待确认时可编辑标题、标签，选择图集及成员图片，并明确排除跳过项。关闭页面、切换空间、重启后端都保留计划。确认后由后端导入；图集页面可返回来源任务。

取消只停止本地执行，保留已提交的远端任务、已有图集及缓存。失败或待处理任务可按当前阶段重试。下载恢复策略是保留已完整下载并通过 SHA-1 核对的文件，对不完整文件重新获取下载地址并整文件下载；不承诺 HTTP 字节续传。

成功后默认清理下载副本和解压产物；「保留源 ZIP」只保留下载的 ZIP。手动清理成功任务会删除全部缓存；清理未完成任务会作废确认计划，重试时重新下载和确认。缓存清理失败不改变导入成功状态。

## 契约和一致性

- 新增 schema 50，由既有迁移注册表和升级前备份机制管理；连接、任务、图集关联和逐文件恢复记录独立存储。通用工作流引擎的节点和状态未扩展，首页引用这条内置模板。
- 状态和阶段分别持久化。远端 info hash、账号身份和精确结果 ID 与任务绑定；远端结果不按文件名猜测。
- 提交意图在调用前提交；响应不明时先按账号和 info hash 查询。查不到则进入待处理，保留歧义，不自动重复提交。已确定的配额、认证和链接拒绝可在处理后重试。
- 图集创建和任务关联同事务；每张图片和对应恢复记录同事务。图片校验与文件写入在事务外，复用既有 imageStore 和 elementService；事务失败会删除尚未入库的文件。已导入成员被删除、移出图集或空间变更时进入待处理。
- 计划保存稳定成员标识、SHA-256、版本及确认记录；执行前核对所选成员，变化时作废计划。每个成员入库前再次检查取消、目标空间和原连接。
- `.secrets/115/<账号>.dpapi` 只保存 DPAPI 密文，账号 Cookie 通过子进程 stdin 传递。无命令行凭证、明文 CLI 配置或普通日志凭证。所有新接口只对本机管理身份开放，LAN 和组织 worker 被拒绝。
- 下载副本和 ZIP 隔离目录位于数据目录 `magnet-import-cache/<任务ID>/`，删除前核对绝对路径及链接。解压拒绝穿越、绝对路径、盘符、链接、Windows 设备名称和重复文件路径；不递归解压嵌套包。

## 执行限制

默认总下载 2 GiB、实际解压/扫描 4 GiB、10,000 个文件、磁盘保留 512 MiB、一次执行最多 30 分钟。图片沿用 25 MiB、4000 万像素、动画最多 200 帧限制；每个图集最多 2000 项。远端只显示排队/运行状态，不把远端百分比当成可靠完成证据。

在数据目录创建 `magnet-import-limits.json` 并重启，可覆盖 `downloadBytes`、`extractedBytes`、`files`、`freeBytes`、`stageMs`。字节上限最多 8 GiB，文件数最多 20,000，执行时间最多 24 小时。ZIP 扫描前按配置的最大展开量预留磁盘。
